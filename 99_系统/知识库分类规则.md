# 知识库分类规则

## 核心原则

### 规则一：OrbitOS 管流程，知识库管沉淀

- `20_项目`、`10_日记`、`90_计划` 负责推进过程
- `40_知识库` 负责稳定、可复用的知识沉淀
- `30_研究` 负责把复杂主题整理成可复用结论

### 规则二：编程与专业知识可以放到外部知识库

- 如果您已有独立知识库仓库，可以通过软链接或手动同步接入
- 开源版不强制绑定任何本机绝对路径
- 是否拆分外部知识库，由使用者自行决定

### 规则三：知识库保持原子化和稳定命名

- 每条知识优先沉淀为一个可复用概念
- 文件名按 `领域编码.两位主题编码-标题.md` 统一
- 技术术语优先使用英文原文，中文作为补充说明

## 知识流动路径

```text
输入/学习 -> 收件箱或研究 -> 项目/研究整理 -> 知识库沉淀
```

### 推荐做法

1. 零散输入先进入 `00_收件箱`
2. 需要系统分析的内容进入 `30_研究`
3. 已稳定的概念再进入 `40_知识库`
4. 与长期执行相关的内容继续留在项目或领域中

## 判断标准

适合放入 `40_知识库` 的内容：

- 已被反复验证的概念
- 可复用的方法、模型、定义、对比
- 未来可能多次引用的知识卡

更适合留在 `30_研究` 或 `20_项目` 的内容：

- 还在探索中的判断
- 强依赖具体上下文的执行细节
- 当下项目的临时草稿和操作记录

## 维护规则

- 不把日记原文直接搬进知识库
- 不把项目待办直接写成知识卡
- 不为相近概念重复建多个名称接近的文件
- 如果分类规则需要变化，先更新本文件，再调整模板和技能
