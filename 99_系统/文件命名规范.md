# 文件命名规范

## 总原则

- 文件名首先服务于检索、排序和长期维护
- 不同目录按职责使用不同命名策略，不强求全库一刀切
- 稳定型内容优先使用稳定标题，不用日期驱动命名
- 过程型内容保留时间维度，用文件名表达形成顺序
- MOC 文件统一使用 `!MOC-[主题].md`

## 各目录命名规则

### `00_收件箱`

- 固定入口文件：
  - `!MOC-收件箱管理.md`
  - `看板.md`
- 临时收件条目：
  - `[YYYYMMDD-HHMM]-[标题].md`

### `10_日记`

- 每日日记：
  - `YYYY-MM-DD.md`
- 月度总结：
  - `YYYY-MM-月度总结.md`
- 固定入口文件：
  - `!MOC-日记系统.md`

### `15_领域`

- 一级领域文件夹使用自然中文名称，例如：`个人成长`、`工作职业`
- 领域主文件优先与文件夹同名
- 子主题文件使用稳定中文标题，不加日期
- 子领域导航文件：
  - `!MOC-[子领域名].md`

### `20_项目`

- 所有项目统一使用文件夹：
  - `[项目名]/`
- 主文件：
  - `[项目名]/[项目名].md`
- 资料文件：
  - `[项目名]/[项目名]-资料.md`
- 复盘文件：
  - `[项目名]/[项目名]-复盘.md`

### `30_研究`

- 研究主笔记：
  - `[YYYYMMDD]-[领域]-[主题或问题].md`
- 专题文件夹使用稳定中文主题名或稳定英文 slug

### `40_知识库`

- 知识卡文件：
  - `[领域编码].[两位主题编码]-[标题].md`
- 固定入口文件：
  - `!MOC-知识库.md`

### `50_资源`

- 快照型资源：
  - `[YYYY-MM-DD]-[来源]-[标题].md`
- 长期参考型资源：
  - `[资源名].md`
  - 或 `[来源]-[主题].md`

### `90_计划`

- 阶段性或专题计划：
  - `[计划主题].md`
- 周期性计划：
  - `[YYYY]-[计划主题].md`
  - 或 `[YYYYQn]-[计划主题].md`

### `99_系统`

- 系统标准文档：
  - `OrbitOS-[主题].md`
  - 或 `[系统模块]-[主题].md`
- 稳定规则文档使用自然中文标题，不加日期
- 讨论类文档：
  - `[主题]-讨论.md`
  - 或 `[主题]-方案.md`

## 知识库领域编码建议

- `AI`：人工智能、模型、Agent、提示词、RAG
- `ARCH`：系统设计、架构模式、分布式
- `NET`：网络、协议、通信机制
- `ALG`：算法、数据结构、复杂度
- `BIZ`：业务机制、支付、交易、运营流程
- `PM`：产品设计、SaaS、增长、用户体验
- `MGMT`：团队协作、管理、评审、沟通
- `EFF`：效率、方法、个人管理
- `THINK`：认知、思考、职业发展

## 执行规则

- 新建文件时，先判断它属于哪个主目录，再套用对应规则
- 如果现有文件名与规则冲突，优先保证链接稳定，再分批迁移
- 若新增目录需要独立命名法，应先更新本文件，再更新对应模板和技能
- 若创建软链接统一入口文件，优先使用仓库内相对路径
